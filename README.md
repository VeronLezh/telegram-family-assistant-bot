# 🤖 Family Assistant Bot

> **Демо-версия для портфолио.** Это анонимизированная копия личного проекта, который реально работает в семье автора. Все имена, Telegram ID, email и ID календарей — вымышленные демо-данные, подробнее см. [раздел «Об анонимизации»](#об-анонимизации).

Асинхронный Telegram-бот на Python, который заменяет собой семейный органайзер: ведёт расписание занятий и тренировок, шлёт напоминания, отвечает на вопросы через LLM (текстом и голосом), синхронизируется с Google Calendar и Google Sheets.

Проект написан «для себя» и находится в активном использовании — это не учебный туториал, а рабочий инструмент с реальными пользователями (семьёй из 4 человек), которым он экономит время каждый день.

## Зачем этот проект в портфолио

Показывает, как я:

- проектирую асинхронное Python-приложение поверх `python-telegram-bot` с несколькими независимыми периодическими джобами (`JobQueue`);
- интегрирую LLM (Groq: `qwen/qwen3.6-27b` для чата и распознавания фото, `whisper-large-v3-turbo` для распознавания голоса) в реальный продуктовый сценарий — не просто чат-бот, а парсинг естественного языка в структурированные действия (добавление напоминаний, событий календаря, тренировок);
- проектирую долговременную память поверх stateless-чата: постоянное «ядро» фактов о каждом пользователе переживает рестарт сервиса, с защитой от переполнения, дублей и prompt injection через собственный текст (`services/memory.py`, покрыто тестами);
- работаю с внешними API (Google Calendar, Google Sheets, Make.com webhooks) и строю ролевую модель доступа поверх Telegram user ID;
- держу код читаемым и небольшим — разделение на `handlers/`, `services/`, `reminders/` вместо одного файла на 2000 строк;
- думаю о безопасности: секреты только через env vars, никаких токенов в коде (см. `.env.example`).

## Возможности

- **AI-чат** с контекстом разговора (до 10 сообщений на пользователя), поддержка текста, голосовых сообщений и фото; жёсткие правила безопасности (без 18+ контента, бережнее с несовершеннолетними) в каждом системном промпте
- **Долговременная память (CORE)**: `запомни, что я не ем мясо` — и AI помнит это в каждом следующем диалоге, даже после рестарта сервиса; ограничена по объёму на пользователя и на факт, с защитой от дублей и от порчи структуры системного промпта
- **Расписание** занятий и тренировок по дням и по членам семьи — редактирование командами и обычным текстом на естественном языке («убери тренировку по вторникам»)
- **Напоминания**: разовые, ежедневные, ежемесячные, «умные» (динамически формулируются AI), персонализированное сообщение дня и алерт о перегруженном дне (с учётом летних каникул)
- **Список подарочных пожеланий** с AI-парсингом сообщений в список и автонапоминанием остальным членам семьи перед днём рождения
- **Google Calendar**: просмотр событий, добавление событий из чата, отдельно личный и семейный календарь
- **Учёт расходов, рассылка, inline-режим** — трата на ЖКХ/детей через меню или текстом (уходит в Sheets через Make.com), рассылка всем (только админ), inline mode бота в Telegram

## Стек

| Слой | Технология |
|---|---|
| Язык / рантайм | Python 3.11+, asyncio |
| Telegram | [python-telegram-bot](https://github.com/python-telegram-bot/python-telegram-bot) v21+ (async API), `JobQueue` для периодических задач |
| LLM / STT | [Groq](https://groq.com/) — `qwen/qwen3.6-27b` (чат, парсинг, фото), `whisper-large-v3-turbo` (голос → текст) |
| Календарь | Google Calendar API (service account) |
| Таблицы | Google Sheets API (расписания, тренировки, напоминания, вишлист, ядро памяти) |
| Healthcheck | Flask, поднимается в отдельном daemon-потоке |
| Интеграции | Make.com (webhook) |
| Деплой | Render (Web Service, start command `python bot.py`) + UptimeRobot пингует `/health`, чтобы инстанс не засыпал |

## Архитектура

```
Telegram
   │
   ▼
Python Bot
   │
   ├──────────────► AI dialogue
   │
   ├──────────────► Scheduler
   │
   ├──────────────► Memory
   │
   ▼
Webhook
   │
   ▼
Make Router
   │
 ┌─┼──────┬───────┬───────┐
 ▼ ▼      ▼       ▼       ▼
Weather Calendar Sheets Notion Polls
```

Python-бот сам ведёт AI-диалог, расписания и напоминания (JobQueue), а часть намерений («погода», «событие», «трата», «покупки», «голосование») параллельно уходит вебхуком во внешний Make-сценарий, где `Router` раскидывает их по интеграциям — подробнее см. [раздел про Make.com](#makecom-no-code-слой-автоматизации) ниже.

```
bot.py              — точка входа: регистрация хендлеров, job queue, polling-цикл с реконнектом
config.py           — пользователи, права доступа, ID календарей, AI-промпты (см. env vars ниже)
server.py           — Flask healthcheck-сервер

handlers/            — обработка входящих апдейтов Telegram
  messages.py         — текст, голос, фото → AI (+ триггеры: напоминание/память/вишлист)
  schedule.py          — расписание занятий
  trainings.py          — расписание тренировок
  expenses.py            — учёт трат ЖКХ и трат на детей через меню
  menu.py                  — главное меню (inline-кнопки)
  admin.py                  — help-команды для админа
  inline.py                   — inline mode

services/            — интеграции с внешним миром
  ai.py                — Groq: чат, парсинг напоминаний, транскрипция голоса, правила безопасности
  memory.py             — долговременное ядро памяти (CORE) на пользователя
  calendar.py             — Google Calendar API
  sheets.py                 — Google Sheets API

reminders/            — доменная логика напоминаний
  jobs.py                — периодические задачи (тренировки, напоминания, ДР, busy-day алерт)
  storage.py                — персистентность напоминаний
  personal.py                 — персональные напоминания пользователей
  wishlist.py                   — список подарочных пожеланий

tests/
  test_memory.py       — тесты ядра памяти (без фреймворка, без сети)
```

Ключевые архитектурные решения:

- **Права доступа только через Telegram user ID** — списки `ADMIN_USERS` / `CALENDAR_PERSONAL_USERS` / `CALENDAR_FAMILY_USERS` в `config.py`, без внешней системы авторизации — это осознанное упрощение для приватного бота с 4 известными пользователями.
- **Всё время — Europe/Moscow** (`config.MOSCOW_TZ`), чтобы не путаться с UTC в напоминаниях и календарных событиях.
- **AI-промпты привязаны к пользователю** (`AI_PROMPTS_BY_USER`) — у каждого свой тон общения с ассистентом.
- **История чата — in-memory**, без БД: осознанный компромисс сложность/нужность для проекта такого масштаба.
- **Долговременная память отделена от истории чата**: история живёт в процессе и исчезает при рестарте, а «ядро» (постоянные факты) хранится в Google Sheets с локальным JSON-фолбэком и подмешивается в системный промпт при каждом обращении к AI — так бот не «забывает» пользователя каждый раз, когда Render перезапускает инстанс.

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env   # и заполнить своими значениями
python bot.py
```

Бот стартует в режиме polling, Flask healthcheck поднимается автоматически в фоновом потоке.

### Тесты

```bash
python tests/test_memory.py
```

Без фреймворка, обычные `assert`. Сеть не трогают: обращение к Google Sheets гасится до импорта, файл ядра памяти уводится во временную папку.

### Переменные окружения

См. `.env.example`:

- `BOT_TOKEN` — токен Telegram Bot API
- `GROQ_API_KEY` — ключ Groq API
- `MAKE_WEBHOOK_URL` — webhook Make.com (опционально)
- `PORT` — порт Flask healthcheck (по умолчанию 5000)

Для Google Calendar / Sheets также нужен файл сервисного аккаунта Google (JSON) — в демо-репозитории он не публикуется, положите свой в корень проекта и укажите путь в `services/calendar.py` / `services/sheets.py`.

## Make.com: no-code слой автоматизации

Часть сценариев, не критичных для основной логики бота, вынесена во внешний no-code сценарий на [Make.com](https://www.make.com/) — бот отправляет туда каждое текстовое сообщение через вебхук (`MAKE_WEBHOOK_URL`, см. `handlers/messages.py` и `handlers/inline.py`), а дальше `Router` в Make разводит его по паттерну текста на отдельные ветки:

| Триггер (текст в чате) | Пайплайн |
|---|---|
| «Погода» | OpenWeatherMap (текущая погода) → Groq (форматирует ответ и совет по одежде) → Telegram Bot (ответ) |
| «Событие \<что\> \<дата\> \<время\>» | Groq (парсит намерение) → JSON parse → Google Calendar (создать событие) → Telegram Bot (подтверждение) |
| «Дети \<имя\> \<на что\> \<сумма\>» | Text parser (regex) → Google Sheets (добавить строку) → Google Sheets (получить итог по ячейке) → Telegram Bot (подтверждение) |
| «Отчет» | Google Sheets (поиск строк) → Tools numeric aggregator → Array aggregator → Telegram Bot (сводка трат) |
| «Голосование \<варианты\>» | JSON transform → Telegram Bot: Make an API call (создание нативного Telegram-опроса) |
| «Покупки \<товары\>» | Text parser → Iterator (по каждому товару) → Notion (создать элемент в БД) → Array aggregator → Telegram Bot (подтверждение) |
| «Список» | Notion (Search Objects) → Tools text aggregator → Telegram Bot (список покупок) |

Почему это вынесено из Python-кода в Make, а не реализовано хендлерами: часть интеграций (Notion, короткие one-off сценарии вроде голосований) меняются чаще самого бота и не требуют деплоя — правится визуально в Make за пару минут, без релиза. Основная же логика (AI-диалог, расписания, напоминания, календарь) обёрнута нативным Python-кодом в этом репозитории, где важны тесты, читаемость и версионирование.
